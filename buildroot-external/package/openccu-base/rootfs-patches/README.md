# openccu-lite: the rootfs patches from OpenCCU

These are OpenCCU's rootfs patches, cut to the sections openccu-lite applies (tasks 388, 389):
only changes to files the image builds and ships - the homematic Tcl package
(`usr/lib/tcl8.2/homematic/`) and the WebUI files openccu-lite keeps at the CCU's paths for
addons (task 331): the device pictures under `www/config/img/devices/`,
`www/config/devdescr/DEVDB.tcl`, `www/config/stringtable_de.txt` and
`www/webui/js/lang/<lang>/translate.lang*.js`. OpenCCU's other patches and sections change the
WebUI, ReGaHss and HMServer's pages, which openccu-lite does not build; they were removed. The
numbers and names stay OpenCCU's, so a patch can be traced to its upstream original.

The numbered directories are the editable source of truth. Each file to be changed is stored as
a pristine `rootfs/path.orig` file and its modified `rootfs/path` file. The adjacent numbered
`.patch` files are generated from them and committed; `series` gives the order.

Regenerate after editing a modified file (Bash 4 or newer, GNU diffutils):

```sh
./create_patches.sh
./create_patches.sh --check
```

The build (`openccu-base.mk`) stages the WebUI files for addons with `stage_lite_www.sh`
(DEVDB.tcl generated by upstream's `create_devdb_tcl.tcl`, in a sorted order) and applies the
series as it is, after `lite_series.py` has checked that every patch changes only those files:
a section on anything else - say, an upstream merge bringing a new WebUI patch - stops the build
and the CI test (`scripts/testcases/lite-webui-files-test.sh`) instead of being applied to a file
that is not there or dropped without a word. Such a patch is not taken, or only its sections on
the files above.

The repository-level `check-openccu-base` target extracts and prunes the pinned OpenCCU-Base,
stages a rootfs with `stage_validation_rootfs.sh` (host tools only: device types, the Tcl
package; no target binaries) and runs `validate_lite_patches.sh`, which applies the series with
zero fuzz (GNU patch and a Tcl interpreter; set `TCLSH` when it is not `tclsh` in `PATH`).

OpenCCU refreshes its complete stack against a complete OpenCCU-Base with `update_patchfiles.sh`
and `validate_patches.sh`; those, `prepare_patch_input.sh`/`finalize_patch_input.sh` (which only
treated `webui.js` and `rega.tcl`) and the WebUI security regression in
`scripts/testcases/security/` were retired here with the WebUI patches (task 389). A patch that
no longer applies after an OpenCCU-Base update is fixed in its workspace and regenerated.
